# Codele — електронний клас з інформатики

Сайт без збірки: звичайні файли, які віддає GitHub Pages.

```
index.html          сторінка (розмітка) і підключення скриптів
css/style.css       вигляд
js/data.js          теми, завдання, уроки
js/core.js          вкладки, сторінка завдання, підказки, марафон
js/worker.js        запуск Python у фоні (Web Worker)
js/menu.js          меню і правила
js/auth.js          вхід, реєстрація, профіль
js/preview.js       вікно tkinter і малюнок turtle
js/tests.js         тести (учень і вчитель)
js/teacher.js       панель вчителя
js/main.js          старт
py/harness.py       Python-код перевірки завдань
```

Число після `?v=` в index.html збільшується при кожному оновленні, щоб браузер не брав старі файли з кешу.

Особисті медалі видно лише самому учневі та вчителю цього класу. Учень не може переглядати чужі медалі чи оцінки; доступ до нагород і оцінок обмежують правила RLS у Supabase. Спільної таблиці медалей учнів немає.

## Ролі та помічники
Перед оновленням сайту виконай у Supabase SQL Editor `supabase/roles_and_helpers.sql` після `supabase/student_awards.sql`. Міграція очікує наявний профіль учителя `dev` і призначає його єдиним глобальним адміністратором. Не змінюй `is_staff()` назад на перевірку всіх імен у `teacher_nicks`: глобальні права мають бути лише в `dev`. Щоб дозволити видалення виданих нагород, окремо виконай `supabase/student_awards_delete.sql`.

У класі власник і призначені повноправні вчителі можуть керувати складом, кодом і звичайною роботою класу. Призначити можна наявний акаунт: учень цього класу після призначення вчителем отримує роль учителя; нові облікові записи створюються через звичайну реєстрацію. Асистент може створювати завдання й тести, перевіряти роботи, ставити оцінки й вручати нагороди, але не керує складом чи кодом і не видаляє акаунти. Помічник-учень бачить код робіт без імені автора та надсилає вчителю пропозицію оцінки; офіційною вона стає лише після підтвердження. Анонімність не приховує дані, які учень сам вписав у код.
